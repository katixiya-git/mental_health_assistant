# 前端 API 调用契约提取报告（供后端补实现对照）

> 分析对象：`心理健康Ai助手/frontendCode/ai-vue/src`
> 约定：axios 实例 `baseURL = '/api'`（`utils/request.js:6`），下文路径均指业务相对路径（如 `/emotion-diary`），实际请求为 `/api/emotion-diary`。
> 响应拦截器（`utils/request.js:27-50`）：后端业务体 `{code, data, msg?}` 中 `code === '200'` 时**直接返回 `data.data`（已剥壳）**，因此视图层拿到的是业务数据本身；`code === '-1'` 视为登录过期（清 token/userInfo 并跳 `/auth/login`，login 接口除外）；其余 code 返回**整个 axios response**（未剥壳）。
> 请求头：拦截器在 `config.headers['token'] = token`（`request.js:16`，小写 `token`），token 来源 `localStorage.getItem('token')`。

后端已实现 6 个接口：`POST /user/login`、`POST /user/add`、`GET /user/current`、`POST /psychological-chat/session/start`、`POST /psychological-chat/stream`(SSE)、`GET /psychological-chat/sessions/{sessionId}/messages`。下面按模块逐一提取契约，未实现的标注【缺】，不一致处标注【疑】。

### 1. POST /user/login 【已实现，前后端对齐】

### 2. POST /user/add 【已实现，前后端对齐】
- 定义：`api/frontend.js:3-5 register(data)`；调用处 `views/register.vue` `submitForm`（L75）。
- 请求体（register.vue:43-52，**整体提交，含 confirmPassword**）：`{ username, email, nickname, phone, password, confirmPassword, gender: 0, userType: 1 }`（gender 0=性别默认，userType 1=普通用户，硬编码默认值）。
- 返回结构假设：注册成功分支依赖**拦截器剥壳后业务负载为假值**（`if (!data)` 才提示"注册成功"，register.vue:77-81）。
- 备注【疑】：register.vue 用 `register(formData).then(({ data }) => ...)` 解构（L75），随后又判 `data.code === "BUSINESS_ERROR"`——这与拦截器约定冲突：code==='200' 时剥壳返回业务负载（无 code 字段），非 200 非 -1 时才返回整个 axios response（其 `.data` 即 `{code,message,...}`）。即"成功"与"业务失败"走的是两套响应形态，代码能成立的前提是注册成功时业务 `data` 为 null/undefined。建议后端确认成功响应剥壳后的值形态。

### 3. GET /user/current 【后端已实现，但前端 src 内未发现调用点】

### 6. POST /psychological-chat/stream (SSE) 【已实现，前后端对齐（注意与设计文档方法差异见下）】
- **不经过 axios**，`consultation.vue:367` 直接 `fetchEventSource('/api/psychological-chat/stream', ...)`（方法 **POST**，路径含 /api 全量；如设计文档写 GET 则与代码不符，代码以 POST 为准）。
- 请求头：`Content-Type: application/json`、`Token: localStorage.getItem('token')`（**大写 Token**，L371；因未走 axios，无小写 token 拦截器）、`Accept: text/event-stream`。
- 请求体：`{ sessionId, userMessage }`（L374-377）。sessionId 来自 startSession 返回值或 `"session_" + session.id`（见 §6/§7 疑点）。
- onopen：校验响应 `Content-Type === 'text/event-stream'`，否则报"非流式数据"（L379-384）。
- **onmessage 解析契约（L385-407）**：
  - 先取 `event.event`（SSE 事件名）。
  - `eventName === 'done'` → 停止（isAiTyping=false、ctrl.abort）并触发情绪分析 `loadSessionEmotion(sessionId)`（L392-397）。
  - 其余事件 `event.data` 须为 **JSON**：`payload = JSON.parse(raw)`；`String(payload.code) === '200'` 且 `payload.data.content` 非空时，把 `payload.data.content` **追加**到当前 AI 消息（增量拼接，`aiMessage.content += payload.data.content`，L401-402）；非 200 时用 `payload.message` 走错误处理（L403-406）。
  - 结论：SSE 每帧 data 是 `{code:'200', data:{content:'<增量文本>'}, message?}` 的业务信封，事件名保留 `done` 作为结束标记。
- onerror/onclose：onclose 也会触发 `loadSessionEmotion`（L412-415）。
- UI 消费字段：AI 消息对象本地字段 `id/senderType:2/content/createAt`；`msg.senderType===2` 走 MarkdownRenderer 渲染 `msg.content`（L156）。

## 八、分页/翻页参数一致性核对（任务指定项）

| 页面/调用 | 接口 | 分页参数 | 返回解构 |
|---|---|---|---|
| consultation.vue `getSessionPage`（L432） | GET /psychological-chat/sessions | `pageNum` + `pageSize` | `res.records`（未取 total） |
| consultations.vue `handleSearch`（L108） | GET /psychological-chat/sessions（同路径） | `currentPage` + `size` | `{records, total}` |
| emotional.vue `handleSearch`（L224） | GET /emotion-diary/admin/page | `current` + `size` | `{records, total}` |
| knowledge.vue `handleSearch`（L82） | GET /knowledge/article/page | `currentPage` + `size` | `{records, total}` |
| frontendKnowledge.vue `getPageList`（L87） | GET /knowledge/article/page | `currentPage` + `size`（+sortField/sortDirection） | `{records, total}` |

结论：
1. 所有分页返回体**均假设 `{records, total}`**，此点前后一致（consultation.vue 只消费 records，忽略 total）。
2. 参数命名**不一致**：`/psychological-chat/sessions` 同一路径两个调用方分别用 `pageNum/pageSize` 与 `currentPage/size`；`/emotion-diary/admin/page` 用 `current/size`；知识库两处用 `currentPage/size`。后端若按 MyBatis-Plus 分页，一般约定 `current/size`，则 knowledge/frontendKnowledge 传 `currentPage`、consultation 传 `pageNum` 均需后端兼容多个别名或前端统一（前端目前未统一，建议后端做参数兼容并在文档标注）。
3. 翻页事件均为 el-pagination `@change(page)` 手动改写当前页号后重查，无 Page 组件内置请求。

## 十、其他值得标注的不一致/风险点（重事实）
1. `msg.createAt` vs `msg.createdAt`：本地 push 的用户/AI 消息用 `createAt`（consultation.vue L297/339/361），模板显示用 `msg.createdAt`（L159），后端 messages 接口返回应为 `createdAt`（consultations.vue L60 也消费 createdAt）——本地消息时间显示会为 undefined，属前端笔误，不影响后端契约。
2. SSE 请求头大写 `Token`（L371）与 axios 小写 `token`（request.js:16）并存，后端两处鉴权解析需都兼容。
3. register.vue 对响应形态的假设与拦截器约定冲突（见 §2 备注），补 /user/add 时最好保持"成功 data 为 null/空"或要求前端改代码。
4. ArticleDialog 创建时 POST body 携带 uuid `id`，与后端主键模型的关系需后端明确（建议后端以该字段为外部业务号或忽略）。
5. 用户端文章列表未过滤 status，后端需默认只返回已发布（或按当前登录用户身份处理），否则前台列表会显示管理端全部状态文章。
6. getSessionList 返回的 `session.id` 与消息/删除/情绪接口的 sessionId 前缀关系：列表 id（裸）→ messages 用裸 id；情绪接口强制拼 `session_`；start 返回的 sessionId 直接用于 stream。建议后端统一 sessionId 形态并核对（若消息接口也期待 `session_xxx`，consultation.vue L445 传裸 id 将 404）。
