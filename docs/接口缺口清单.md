> 结论基准：后端当前只实现 6 个接口，前端实际调用的接口共 22 个，其中 16 个待后端补齐。

## 0. 通用口径（前后端约定，补接口时必须遵守）

- axios 实例 `baseURL = '/api'`（`frontendCode/ai-vue/src/utils/request.js:6`），下文路径均为相对 `/api` 的业务路径。
- 响应信封 `Result<T>{code, msg, data}`（`backendCode/ai-project/.../common/Result.java`），`code` 为**字符串**。
- 响应拦截器（`request.js:27-50`）：`code === '200'` 时**剥壳直接返回 `data.data`**（视图层拿到的即业务数据）；`code === '-1'` 视为登录过期；其余 code 返回**整个 axios response**（视图层需从 `res.data` 取信封）。
- 请求头两套并存，后端鉴权解析需都兼容：axios 走小写 `token`（`request.js:16`）；SSE 直连 `fetchEventSource` 走大写 `Token`（`views/consultation.vue:371`）。
- 分页返回体统一为 `{records, total}`；但**参数命名三套并存**（见 §3 R1），后端建议做别名兼容。

## 3. 实现前需拍板的契约决策点

- **R1 分页参数三套命名**：`pageNum/pageSize`（会话用户端）、`currentPage/size`（会话管理端 + 知识库）、`current/size`（情绪日志）。建议后端统一别名兼容（如自定义 PageParam 解析），或顺带统一前端。
- **R2 sessionId 形态**：消息接口传裸 id、情绪接口强制 `session_` 前缀、start 返回的 sessionId 直接用于 stream。后端 `SessionServiceImpl.parseSessionId` 已兼容两种前缀，**新接口务必复用**。
- **R3 注册响应形态（前端已修 2026-09-08）**：register.vue 曾误判 `code==='BUSINESS_ERROR'`/`message` 字段；现在按拦截器约定判定 `res.data.code!=='200'` 且读 `msg`。**后端补接口继续返回 `{code,msg}` 信封即可，勿自定义 code 文案。**
- **R4 文章创建携带 uuid `id`**：`businessId` 为每次上传随机 uuid，POST body 一并携带；若文章主键为自增 Long 需决定忽略/外部业务号。PUT 路径参数为真实主键，两者语义勿混。
- **R5 tags 与 tagArray**：编辑回显/详情需同时给 `tags`（逗号串）与 `tagArray`（数组），或二选一并前端适配。
- **R6 前端已修小 bug（2026-09-08）**：consultation.vue 消息本地字段 `createAt`→`createdAt`；emotional.vue 表头「用户ID/会话ID」错位改为「日记ID/用户昵称」。
- **R7 fileBaseUrl 外网地址** `http://159.75.169.224:1235`：文件存储若改本地/OSS，config/index.js 与拼接逻辑需同步改。

## 4. 建议落地顺序（依赖关系）

1. `POST /user/logout`（最小、独立）
2. 情绪日记：`POST /emotion-diary` → `admin/page` + `DELETE`（`aiEmotionAnalysis` 可先存 JSON 空对象）
3. 知识库：`category/tree` + 文章 CRUD/status + `file/upload`（连带 article/文件表设计）
4. 咨询会话补充：`sessions` 列表 + `DELETE` + `session/{id}/emotion`（复用 SessionService，`ConsultationSession.lastEmotionAnalysis` 字段已预留）
5. `GET /data-analytics/overview`（依赖 2/3/4 数据，最后做）
